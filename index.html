GRC Compliance Dashboard

Executive posture across six program modules, built from a dashboard-as-code data pipeline

Key Performance & Risk Indicators

Six board-level KPIs / KRIs, each with a target, current value, and a red-amber-green status derived automatically in the aggregation pipeline. Direction (higher- or lower-is-better) determines how each metric is scored against its target.

Module Compliance Breakdown

Per-module control counts and compliance percentage. Compliance is scored on fully-implemented controls only; the inline bar shows compliant (green) versus partial (amber) versus missing (red).

ModuleFrameworkControlsComplianceStatus

Click any row to expand the compliant / partial / missing breakdown, owner, and last review.

Risk Trend — Inherent to Residual

Aggregated inherent and residual risk scores from the Enterprise Risk Register over the last six months, showing the effect of mitigation activity across the program.

Inherent risk (before controls) Residual risk (after controls)

Remediation Tracker

Open corrective-action plans (CAPs) drawn from audit findings and risk treatments, each with an owner, due date, progress, and overdue flag. Overdue items feed directly into the KPI panel.

Data Pipeline — Dashboard as Code

This dashboard is not hand-maintained. Each module exports a control-status matrix; a scheduled pipeline normalises those exports, computes every number on this page, and writes a single dashboard.json the front-end reads. The same rollup is expressed in Python (pandas), queried in SQL, orchestrated in Bash, and fed from Microsoft 365 via PowerShell.

Data Flow

Six module sources feed one aggregator, which emits a single dashboard.json consumed by both the executive dashboard and the board report.
